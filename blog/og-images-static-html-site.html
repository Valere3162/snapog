How to Add OG Images to Any Static HTML Site

No framework, no build step, no JavaScript required. Whether you're on GitHub Pages, Netlify, a bare HTML file, or a Hugo blog — you can have polished social preview images live in under five minutes.

Why static sites miss out on social previews

When someone shares your link on Twitter, LinkedIn, or in Slack, the platform fetches your page's <meta> tags and looks for an og:image. If it finds nothing — or finds a broken image — the link unfurl shows a plain grey box. That grey box kills clicks.

Framework users have it easy: Vercel ships ImageResponse, Next.js App Router has opengraph-image.tsx, Astro has @astrojs/og. But if you're running plain HTML, a Jekyll blog, a Hugo site, or a simple GitHub Pages project, none of that exists. You're on your own.

The usual workarounds — Canva exports, hand-crafted PNGs, static image files — break the moment a page title changes. They don't scale, and they look inconsistent across your site.

The fix

An OG image URL is just a URL. If that URL returns an image, you're done. SnapOG lets you construct that URL from query parameters — no server required on your end.

How URL-based OG images work

SnapOG exposes a single endpoint:

URL PATTERN
https://api.snapog.dev/og?title=Your+Page+Title&subtitle=Your+Tagline&theme=dark

That URL returns a 1200×630px PNG — the canonical OG image size. You put that URL directly in your og:image meta tag. No build step. No file to host. No CDN to configure.

The image is generated on the fly, cached at Cloudflare's edge, and served from 200+ locations globally. Latency is under 50ms for virtually all social crawlers.

Step-by-step: Adding OG images to a static HTML page

  1. 1

    Get your API key

    Sign up at snapog.dev. The free tier gives you 10,000 images/month — more than enough for a static site.

  2. 2

    Add the meta tags to your <head>

    For each HTML page, add these five meta tags:

    YOUR-PAGE.html — <head>
    <!-- Required OG tags -->
<meta property="og:title"       content="Your Page Title" />
<meta property="og:description"  content="A one-sentence summary of your page." />
<meta property="og:url"         content="https://yoursite.com/your-page" />
<meta property="og:type"        content="website" />

<!-- OG image via SnapOG -->
<meta property="og:image" content="https://api.snapog.dev/og?title=Your+Page+Title&subtitle=Your+Tagline&theme=dark&key=YOUR_API_KEY" />
<meta property="og:image:width"  content="1200" />
<meta property="og:image:height" content="630" />

<!-- Twitter Card (optional but recommended) -->
<meta name="twitter:card"        content="summary_large_image" />
<meta name="twitter:title"       content="Your Page Title" />
<meta name="twitter:description"  content="A one-sentence summary." />
<meta name="twitter:image"       content="https://api.snapog.dev/og?title=Your+Page+Title&subtitle=Your+Tagline&theme=dark&key=YOUR_API_KEY" />

    Replace Your+Page+Title and Your+Tagline with URL-encoded versions of your text (spaces become + or %20).

  3. 3

    Preview the image before publishing

    Paste the full URL into your browser. You'll see the image immediately. No cache to purge, no deploy to wait for.

    BROWSER URL BAR
    https://api.snapog.dev/og?title=My+Blog+Post+Title&subtitle=My+Site+Name&theme=dark&key=YOUR_API_KEY
  4. 4

    Validate with a social debugger

    Use the Meta Sharing Debugger or the Twitter Card Validator to confirm your tags are read correctly. Both tools show you exactly what a social crawler sees.

Available parameters

Parameter Default Description
title—Main headline (required). URL-encode spaces as +.
subtitle—Secondary line below the title. Good for your site name or category.
themedarkdark or light. Dark renders a dark background, light renders white.
logo—URL of a logo image to embed. Must be publicly accessible.
bg—Background hex color (e.g. 1a1a2e). Overrides theme background.
key—Your API key. Required for requests beyond the anonymous trial limit.

Platform-specific examples

GitHub Pages / bare HTML

Works out of the box. Add the meta tags to each .html file's <head>. GitHub Pages serves static files — the OG image lives at SnapOG's CDN, so there's nothing to configure on your host.

Jekyll (_layouts/default.html or post.html)

_layouts/post.html — inside <head>
{%- assign og_title = page.title | url_encode -%}
{%- assign og_sub   = site.title  | url_encode -%}

<meta property="og:image"
      content="https://api.snapog.dev/og?title={{ og_title }}&subtitle={{ og_sub }}&theme=dark&key={{ site.snapog_key }}" />

Put your API key in _config.yml as snapog_key: sk_live_…. Jekyll templates handle the variable substitution at build time — each post gets its own unique OG image automatically.

Hugo (layouts/partials/head.html)

layouts/partials/head.html
{{- $title := .Title | urlquery -}}
{{- $sub   := .Site.Title | urlquery -}}

<meta property="og:image"
      content="https://api.snapog.dev/og?title={{ $title }}&subtitle={{ $sub }}&theme=dark&key={{ .Site.Params.snapogKey }}" />

Set snapogKey in your hugo.toml under [params]. Hugo's urlquery function handles URL-encoding for you.

11ty (Eleventy)

_includes/head.njk
{%- set ogTitle = title | urlencode -%}
{%- set ogSub   = site.name | urlencode -%}

<meta property="og:image"
      content="https://api.snapog.dev/og?title={{ ogTitle }}&subtitle={{ ogSub }}&theme=dark&key={{ site.snapogKey }}" />

Common mistake

Don't forget to URL-encode your title. A title like It's Working! must become It%27s+Working%21 in the URL. Most template engines have a built-in filter for this (url_encode, urlquery, urlencode).

How caching works

The first time a URL is requested, SnapOG renders the image and caches it at Cloudflare's edge. Subsequent requests for the same URL return the cached copy — so social crawlers that hammer your links in parallel get fast, consistent responses.

If you change a page title, just update the title= parameter. The new URL gets a fresh render; the old URL stays cached (harmlessly). No manual cache purge required.
