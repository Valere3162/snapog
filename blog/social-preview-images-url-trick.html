The Laziest Way to Generate Social Preview Images (A URL Trick)

You don't have to write any code to get great social previews. One URL does it all. This is the lazy developer's guide to OG images that actually look good.

Your Link Looks Terrible in Slack

You ship something. You paste the link into Slack, Twitter, Discord. Everyone sees a gray box with your site title in a default font. Sometimes just the URL. Nobody clicks it.

The fix is not a redesign. It's not a Satori setup or a custom API route. It's one URL parameter. You paste it into a <meta> tag and it's done. Your link unfurls with a polished 1200×630 image in Slack, a proper Twitter Card, a rich preview in iMessage — everywhere social crawlers look.

The trick: let a URL do the rendering for you.

The Trick: One URL, Zero Code

SnapOG is a URL-based OG image API. You describe what you want in query parameters, and it returns a 1200×630 PNG. No signup needed to see it — try opening this in a new tab:

https://api.snapog.dev/og?title=My+Article&subtitle=mysite.dev&theme=dark&logo=https://mysite.dev/favicon.png

Here's what each parameter does:

Param What it does Example
title Main headline — the big text on the image My+Article+Title
subtitle Secondary line — domain, author, category mysite.dev
theme dark or light — controls the color scheme dark
logo URL to your logo or favicon — shown top-left https://...
tag Small label badge — category, section, type Tutorial

To use it, drop the URL directly into your <head>:

HTML — drop this in your <head>
<meta property="og:image"
      content="https://api.snapog.dev/og?title=My+Article&subtitle=mysite.dev&theme=dark" />
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:image"
      content="https://api.snapog.dev/og?title=My+Article&subtitle=mysite.dev&theme=dark" />

That's it. Ship it.

Tip

URL-encode spaces as + or %20. Most HTML is fine with either, but + reads cleaner in source. Avoid special characters in the title — strip them or encode them.

5 Places This Works Right Now

  • Static sites (Jekyll, Hugo, 11ty, plain HTML) https://api.snapog.dev/og?title=Your+Post+Title&subtitle=yourblog.com&theme=dark
  • Ghost or WordPress blogs — no plugin needed https://api.snapog.dev/og?title={{post.title}}&subtitle={{@site.title}}&tag={{primary_tag.name}}&theme=dark
  • GitHub project pages and README link previews https://api.snapog.dev/og?title=my-cool-lib&subtitle=github.com/you&tag=Open+Source&theme=dark
  • Email newsletters (link preview in mail clients) https://api.snapog.dev/og?title=Issue+%2342%3A+What+I+Shipped&subtitle=yourname.substack.com&theme=dark
  • Slack/Discord link drops and internal tool dashboards https://api.snapog.dev/og?title=Q3+Revenue+Dashboard&subtitle=internal.yourco.com&tag=Finance&theme=dark

In each case the pattern is identical: build a URL, put it in the og:image tag, done. No build step, no npm package, no edge function, no font wrangling.

When to Stop Being Lazy and Write Code

The URL trick covers 80% of cases. But there are two situations where you genuinely need something more:

  • Truly dynamic titles from a CMS. If your post title comes from a database query at request time, you'll want to build the SnapOG URL server-side and inject it into your template. That's a few lines of string interpolation, not a Satori setup.
  • Per-user or per-session content. User profile pages, personalized dashboards, anything where the image content is unique per visitor — there you want programmatic URL construction.

For the Next.js App Router pattern — constructing the URL inside generateMetadata with full Prisma/Node access, no edge runtime required — read Dynamic OG Images in Next.js Without Writing Satori JSX. It covers the full setup in about 15 lines of code.

But if you're reading this and you haven't shipped OG images yet because the setup looked complicated: start with the URL trick. You can always upgrade later.
