Open Graph Images Explained: What They Are, Sizes & How to Generate Them

Sep 2026 · 7 min read · SnapOG

When you share a link on Twitter, Slack, LinkedIn, or iMessage, a preview card appears with a title, description, and image. That image is your OG image — defined by Open Graph meta tags in your page's <head>. If you don't set one, platforms fall back to a random image from your page, your logo, or nothing. This guide explains exactly how OG images work, what sizes to use, and how to generate them automatically.

What is the Open Graph protocol?

Open Graph (OG) is a protocol created by Facebook in 2010 to standardize how web pages present themselves when shared on social platforms. It uses <meta> tags in the <head> of your HTML to tell platforms what title, description, image, and type to display in link previews.

The core tags:

HTML <head>
<!-- Required -->
<meta property="og:title" content="Your Page Title" />
<meta property="og:description" content="A short description of your page." />
<meta property="og:image" content="https://yourdomain.com/og-image.png" />
<meta property="og:url" content="https://yourdomain.com/your-page" />
<meta property="og:type" content="website" />

<!-- Recommended -->
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta property="og:site_name" content="Your Site" />

Twitter (X) uses its own variant called Twitter Cards, which overlaps significantly with OG:

HTML <head>
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:title" content="Your Page Title" />
<meta name="twitter:description" content="A short description." />
<meta name="twitter:image" content="https://yourdomain.com/og-image.png" />
Good news

Twitter falls back to og:image if no twitter:image is set. In practice, you need both: og:image for all platforms, and twitter:card + twitter:image for X/Twitter to render correctly with the large image format.

The safe zone: Keep important content (logo, title) within the center 80% of the image. Platforms apply crops differently, and the edges may be cut off in some previews.

File size: Keep your OG image under 1MB. Larger images cause some platforms to time out or skip the preview entirely. PNG or JPEG both work — PNG is sharper for text, JPEG is smaller for photographic content.

Common OG image mistakes

1. Not setting og:image at all

Without an OG image, Facebook uses a random image from your page. Twitter shows no image. LinkedIn shows nothing. Every link share is a missed branding opportunity.

2. Using a relative URL

The og:image value must be an absolute URL with protocol. /images/og.png will not work. Use https://yourdomain.com/images/og.png.

3. Image too small

Facebook requires at least 200×200 pixels. LinkedIn recommends at least 1200×627. Images that are too small are either rejected or displayed poorly.

4. Important content near the edges

Slack and iMessage apply crops. If your logo or main text is near the edge of a 1200×630 image, it may be cropped out in some previews. Use a centered safe zone.

5. Same OG image for every page

A single generic OG image for your whole site loses click-through potential. Each blog post, product page, and campaign should have a unique OG image that describes the content. This is the main problem that OG image generators solve.

How to generate OG images

Option 1: Static images (Figma/Canva)

Create a template in Figma or Canva, export at 1200×630 PNG, upload to your CDN. Works fine for small sites with infrequent content updates. Doesn't scale to blog posts or dynamic content.

Option 2: Generate in code (Satori / Puppeteer)

For Next.js, Vercel's @vercel/og library lets you generate OG images at the edge using Satori (a JSX-to-SVG renderer). It's powerful but requires specific JSX syntax, limited CSS support, and font loading setup. See our Next.js OG image guide for when this gets painful.

Option 3: URL-based API (SnapOG)

The simplest approach for most sites: generate OG images on-demand via URL parameters. Set your og:image to a SnapOG API URL with your title and theme, and every page gets a unique, properly-sized OG image with zero code:

HTML <head>
<!-- Static page -->
<meta property="og:image"
  content="https://api.snapog.dev/og?title=Your+Page+Title&subtitle=yourdomain.com&theme=dark" />

<!-- Blog post (dynamic) -->
<meta property="og:image"
  content="https://api.snapog.dev/og?title={{ post.title|urlencode }}&subtitle=Your+Blog&theme=dark" />

This works in any templating language (Jinja2, Liquid, Handlebars, ERB) without any build step or server-side code change. Every page gets a unique OG image based on its title.

Checking your OG tags

After adding OG tags, verify them before sharing:

  • Facebook Sharing Debugger — scrapes your page and shows exactly what Facebook sees. Also clears the cache for updated pages.
  • Twitter Card Validator — validates Twitter Card tags and shows a preview.
  • LinkedIn Post Inspector — shows the LinkedIn preview and re-scrapes on demand.
  • opengraph.xyz — quick cross-platform preview without needing platform accounts.
Cache buster tip

If you update an OG image and platforms still show the old one, add a cache-busting query parameter to the image URL: ?v=2. Platforms treat a URL change as a new image and re-fetch it.

OG image best practices

  • Use 1200×630px as your canonical size — it works everywhere.
  • Keep file size under 1MB — larger files cause fetch timeouts on slow connections.
  • Use absolute URLs for the og:image value.
  • Include both og:image and twitter:image — don't rely on Twitter's fallback.
  • Make every page unique — generic OG images underperform content-specific ones significantly.
  • Test before you publish — use opengraph.xyz or your platform's debugger tool before your content goes live.
  • Keep important content centered — edges may be cropped by some platforms.
