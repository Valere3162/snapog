Why Your Links Look Bad in Slack
(And How to Fix It)

Slack's link unfurling is picky. Here's exactly what it requires — and how to generate an OG image that passes every check in minutes.

Sep 2026 · 7 min read · SnapOG

You paste a link into Slack. Instead of a rich preview with an image, your colleagues see a one-line text citation: just the URL and maybe a title. Nobody clicks it. This is the Open Graph gap — and it's more common than it should be, because Slack's unfurling system is stricter than Twitter or iMessage about what it will display.

This guide explains exactly what Slack's unfurler requires, the four most common reasons your image isn't showing, and how to add a compliant OG image to any site in under ten minutes.

How Slack link unfurling works

When you paste a URL into Slack, Slack's server-side crawler fetches that URL and reads its <meta> tags. It's looking for the Open Graph protocol — specifically og:image, og:title, and og:description. If it finds a valid image, it renders the rich preview. If anything is missing or broken, you get the text-only fallback.

Three things distinguish Slack's crawler from other platforms:

  • It uses its own user agent (Slackbot), not Googlebot. Some servers accidentally block unfamiliar crawlers.
  • It has stricter image size requirements than Twitter or LinkedIn. Images below 500×262px will not display.
  • It caches aggressively. Once Slack fetches a URL, it caches the result for up to 30 minutes. Updating your meta tags won't immediately fix existing Slack messages.

The four reasons your image isn't showing

Reason 1: No og:image tag at all

The most common issue. Many sites — especially developer tools, documentation sites, and early-stage products — simply don't have OG meta tags yet. Slack falls back to text-only with nothing to display.

Check it: View source on your page and search for og:image. If it's not there, that's your problem.

Reason 2: Image is too small

Slack requires a minimum image size of 500×262 pixels. Images below this threshold will be ignored and Slack will display the text fallback even if the meta tag exists.

The widely recommended OG image size is 1200×630px (2:1 aspect ratio). This works on Slack, Twitter, LinkedIn, and Facebook simultaneously. Don't use a smaller image thinking it will display faster — it just won't display at all on Slack.

Reason 3: Image URL returns a non-image content type

Your og:image URL must return Content-Type: image/jpeg, image/png, or image/gif. If it returns text/html (a redirect to a login page), application/octet-stream, or throws a 404/403, Slack won't display it.

This often happens when:

  • Your image is behind authentication
  • Your CDN serves images with incorrect MIME types
  • You're using a dynamically generated image URL that errors in production

Reason 4: Slack's cache is serving an old result

If you recently added or fixed your OG tags, Slack may be serving a cached version of the old (broken) preview. This is frustrating but temporary — Slack's cache typically expires within 30 minutes.

Force cache invalidation

You can force Slack to re-fetch a URL by pasting it with a cache-busting query parameter: https://yoursite.com/page?v=2. Slack treats this as a new URL and fetches fresh metadata. Remove the parameter afterward.

The correct meta tag structure

Add these to the <head> of every page you want to look good in Slack:

HTML meta tags
<!-- Open Graph / Slack unfurl -->
<meta property="og:type" content="website" />
<meta property="og:url" content="https://yoursite.com/page" />
<meta property="og:title" content="Your Page Title Here" />
<meta property="og:description" content="A clear, one-sentence description of this page." />
<meta property="og:image" content="https://yoursite.com/og-image.png" />

<!-- Optional but useful for Twitter/X -->
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:image" content="https://yoursite.com/og-image.png" />
Common mistake: Setting og:image to a relative path like /og-image.png. It must be an absolute URL including the protocol and domain. Slack's crawler fetches this URL directly — relative paths don't resolve.

Testing your Slack preview before going live

Use these tools to validate your OG tags without waiting for Slack's cache:

  • Slack: Paste your URL in any Slack channel and watch the preview render live (or not)
  • OpenGraph.xyz: Paste your URL to see how it renders across platforms including Slack
  • LinkedIn Post Inspector: Validates OG tags and shows the LinkedIn preview (similar requirements to Slack)
  • curl check: curl -I https://yoursite.com/og-image.png — verify the Content-Type header is correct and the status is 200

Slack preview troubleshooting checklist

  • ✓

    og:image tag exists — view-source and search for og:image

  • ✓

    og:image URL is absolute — starts with https://, not /

  • ✓

    Image is at least 500×262px — ideally 1200×630px

  • ✓

    Image URL returns HTTP 200 — curl the URL to verify, no redirects to login

  • ✓

    Content-Type is image/* — must not return text/html

  • ✓

    Image is under 5MB — Slack silently drops images above this

  • ✓

    og:title and og:description are set — Slack shows these alongside the image

  • ✓

    Slackbot isn't blocked — check robots.txt and server-level bot blocking rules

Why this matters beyond aesthetics

Slack is where teams share links internally — product announcements, blog posts, landing pages, tool recommendations. A rich preview with a professional image gets roughly 3× more engagement than a plain URL. When your company shares your product in a Slack community, a broken preview signals "unfinished" before anyone reads a word.

For SaaS products and developer tools specifically, Slack is a discovery channel — communities like #tools, #show-and-tell, and #random in developer Slack groups are where links circulate. A broken OG image is a conversion that never happens.
